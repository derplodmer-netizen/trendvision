# Trend Radar — сигнальный бот для BinoDex (отдельный от Kairo)

Только сигналы — без автоторговли. По ТЗ 3, вынесено в отдельного бота.

## Что делает
- **Подписка на канал:** при `CHANNEL=@username` бот открывается только после подписки (кнопки «Подписаться» и
  «Я подписался», проверка getChatMember; бот должен быть админом канала). Если проверка сломана — человека пускают, в логе ошибка.
- **Воронка:** приветствие → сигналы и итоги (открытая статистика + 1 бесплатный сигнал в час) → регистрация по смарт-ссылке
  → человек присылает свой ID BinoDex → проверка через Partner API (аккаунт наш?) → пополнение → доступ.
  В чате остаётся только текущий шаг.
- **Проверка пополнения:** Partner API (`depositsCount` / `firstDeposit`) — по кнопке сразу, в фоне каждые 10 минут
  для привязанных за последние 14 дней и раз в 3 часа для остальных. Доступ открывается сам, с сообщением.
- **Сигнал по запросу:** «Получить сигнал» → пара (или «Авто» — пара с самым чётким входом сейчас) → экспирация
  (SIGNAL_EXPIRIES) → бот смотрит котировки BinoDex прямо сейчас (публичные `/broker/pairs/binary` и `/broker/chart`,
  свечи 5 с) и даёт направление. Если индикаторы (EMA 8/21, RSI 14, импульс) не сходятся сильнее SIGNAL_MIN_STRENGTH —
  честно пишет «входа нет» и предлагает пару, где вход есть. Лимитов нет, кроме одного: по паре, где у человека уже есть
  открытый сигнал, второй не выдаётся до итога. До пополнения — 1 бесплатный сигнал, под ним «Получить доступ»; повторная попытка ведёт на регистрацию.
- **Итог** каждого сигнала считается по цене BinoDex на момент экспирации и приходит ответом под сигналом. Все выданные
  сигналы идут в открытую статистику. Без котировок на момент экспирации — «не учитывается», в процент не входит.
- **Рассылка сильных входов:** только при согласии индикаторов от BROADCAST_MIN_STRENGTH, не больше BROADCAST_PER_DAY
  в сутки и не чаще раза в BROADCAST_GAP_MIN, не в тихие часы; всем, кто нажал старт и не выключил их.
  Новичкам — как тест: «это пример сигнала, итог придёт сюда же», кнопки «Получить доступ», регистрация, «Не присылать».
- **Меню:** получить сигнал, статистика (сегодня / 7 / 30 дней, по парам), уведомления вкл/выкл, открыть BinoDex.

## Запуск
1. `cp .env.example .env`, заполнить BOT_TOKEN, PARTNER_API_KEY, ADMIN_TOKEN.
2. `pip install -r requirements.txt && python -m app.main` (или Docker).

## Админ-API (`Authorization: Bearer <ADMIN_TOKEN>`)
- `GET /admin/funnel?days=7&by=tag|ab` — start → value → free_signal → register → registered → ftd, расход, цена FTD, ROI.
- `PUT /admin/spend`, `GET|PUT /admin/texts`, `GET /admin/postbacks`.
- `GET /admin/signals` — сигналы, итоги, процент за 1/7/30 дней.

## Тесты
`python -m pytest -q`

## Картинки
`media/*.jpg` (1280×720): экраны воронки, сигнал вверх/вниз, «Сильный вход», итог в плюс/минус; `media/avatar.jpg` (640×640,
/setuserpic) и `media/description.jpg` (640×360, /setdescriptionpic) для @BotFather.
Стиль — финтех: почти чёрный фон, один салатовый акцент (красный для «вниз» и минуса), заголовок Inter Tight с цветной
точкой, справа — кусок интерфейса продукта (карточка сигнала, список итогов, статус, меню). Все числа на картинках
подписаны как пример.

**Живые карточки.** Картинку к каждому сигналу и итогу бот рисует сам в момент отправки (`app/cardgen.py`, Pillow,
~30 мс): фон из `media/bg/*.jpg` + карточка с реальными данными — пара, выплата BinoDex, вверх/вниз, экспирация,
«вход до» по Киеву и график последних котировок этой пары; у итога — путь цены от входа до экспирации,
уровень входа и цены входа/экспирации. Одна картинка на сигнал (у рассылки — одна на всех), Telegram хранит её по file_id.
Если нарисовать не вышло — уходит статичная картинка.

Перерисовать статичные: `python tools/render_cards.py` (Playwright + Chrome, только на машине дизайнера).
